# gamedig: where the game data comes from

[node-gamedig](https://github.com/gamedig/node-gamedig) (MIT, Node.js) queries game servers for 362 games over 79 protocols. Looked at v5.3.3, commit `41f3773` (Aug 2026).

**It does not discover servers.** You give it a type, host and port and it asks that one server. Finding servers is this project's job. What we take from gamedig is the knowledge of **which port to ask and which protocol to speak** for each game, and its protocol code as a reference when writing our own decoders.

## The data in this package
`gamelan/gamedig/`, generated by `tools/sync_gamedig.mjs`:

| File | Shape | Use it to |
|---|---|---|
| `games.json` | `{"_meta": {...}, "games": {id: {name, release_year, protocol, game_port, query_port, query_port_offset, query_ports[], lan_queryable, old_ids[], has_notes}}}` | Name a game; know which ports and protocol it uses |
| `protocols.json` | `{"protocols": {id: {extends, transports[], lan_queryable, source_file, games[]}}}` | Pick what to implement; skip internet-only protocols |
| `query-ports.json` | `{"ports": [{port, protocols[], games[]}, ...]}` most-shared first | The list of ports to sweep, and which decoders to try on each |

`query_ports` follows gamedig's own rule (`lib/QueryRunner.js`): game port + each `port_query_offset`, then the fixed `port_query` if set.

Refresh: `git clone --depth 1 https://github.com/gamedig/node-gamedig /tmp/node-gamedig && node tools/sync_gamedig.mjs /tmp/node-gamedig`

## Where things live in gamedig
| Path | What |
|---|---|
| `lib/games.js` | The game database everything above is generated from |
| `lib/QueryRunner.js` | Query port rules (offsets, fixed query port) |
| `lib/Results.js` | Result shape: name, map, password, numplayers, maxplayers, players[], bots[], connect, ping, raw. Close to our `ServerInfo` |
| `protocols/valve.js` | Steam A2S, 137 games. Also handles split packets and the player/rules queries we don't do yet |
| `protocols/gamespy1.js`, `gamespy2.js`, `gamespy3.js` | 101 games, mostly older titles |
| `protocols/quake2.js`, `quake3.js` | Quake family: Call of Duty 1–4, Wolfenstein, OpenArena, Xonotic |
| `protocols/minecraft.js` → `minecraftvanilla.js` (TCP), `minecraftbedrock.js` (UDP) | Minecraft Java and Bedrock |
| `protocols/unreal2.js`, `ase.js`, `doom3.js` | Next most common |
| `GAMES_LIST.md` | "Not supported (yet)" list (~line 370) and per-game notes, e.g. games that need querying enabled on the server |

## Facts that matter for this project
- **Valve A2S is 38% of all games.** Top protocols by game count: valve 137, gamespy1 72, gamespy2 22, quake3 21, ase 12, gamespy3 7, unreal2 7. The top four families (Valve, GameSpy, Quake, Minecraft) cover about 75%.
- **Port 27015 alone is 86 games.** The 100 most-shared ports cover 80% of LAN-queryable games.
- **A port does not identify a game.** 7777 is shared by 18 games across 7 protocols. Probe by port, identify by the reply. For Valve, the reply's Steam `app_id` identifies the game exactly.
- **15 games are internet-only** (`lan_queryable: false`): protocols `epic` (Ark: Survival Ascended, Squad, Renown, The Isle Evrima), `factorio`, `discord`, `altvmp`, `ragemp`, `scpsl`, `geneshift`, `minetest`, `renegadex`, `brokeprotocol`, `hawakening`, and the `*master` ones. They ask an online service, so they can't see LAN-only servers. Skip them.
- **Some games need querying enabled on the server**: Valheim, Terraria (TShock), Conan Exiles and others in `GAMES_LIST.md` notes.

## How this fits the plan in the README
1. Source / Steam query: started (`gamelan/source.py`). gamedig's `valve.js` shows split-packet and A2S_PLAYER handling for later.
2. **A games data file:** this is it. `games.json` names games and `query-ports.json` says which ports to try.
3. The unknown list: a reply on a port in `query-ports.json` that no decoder understands is a strong "unknown game" candidate; the port's `games` list gives the likely titles.
4. Minecraft, 5. Quake 3 / GameSpy / Unreal, 6. one-offs: port from the gamedig files listed above, in order of `protocols.json` game count.

Beyond broadcast, a **targeted sweep** becomes possible: for each live host on the LAN, probe the top ports in `query-ports.json` with the decoders listed for that port. Paced slowly so it never affects anyone's game.

For the protocols we don't port, running gamedig itself (its CLI, or as a Node library on the GXL Event Server) is a fallback.
